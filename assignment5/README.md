# A5：图像描述实验与数据集替换说明

## 为什么更换数据文件

原作业使用课程预处理好的 `coco.pt`。本次配置环境时，由于原来实验网站挂了，原下载地址返回 HTTP 404；检查课程作业仓库和其他公开来源后，未找到确认兼容的原始文件。因此无法按原链接直接复现实验。

为了继续完成 RNN、LSTM 和 AttentionLSTM 的实现、训练及可视化，改为从 **MS COCO 2014 官方图片和真实描述标注**重新构建一个作业格式兼容的子集。

这里并不是换成了另一个图像描述数据集：数据来源仍是 COCO 2014，但**样本选择、词表和预处理不等同于课程提供的 `coco.pt`**。生成的数据沿用 `coco.pt` 文件名，只表示读取接口兼容，不能将它当成恢复了原课程文件。描述来自官方标注，不是模型生成的替代标签。

## 如何构建，以及为什么这样处理

由 [prepare_coco2014.py](prepare_coco2014.py) 下载官方描述标注和所需原始图片，再生成 `datasets/coco.pt`。只下载选中图片，不下载全部图片压缩包，减少下载时间和磁盘占用。

- 保留官方 train/val 划分，并使用固定随机种子选样；训练与验证的图片 ID 不重叠，避免图片泄漏。
- 训练集选取 2,000 张图片，每张配 5 条真实描述，共 10,000 个图像—描述对；验证集为 100 张图片、500 个配对。配对数不等于独立图片数。
- 图片转换为 RGB、缩放到 112×112，以 CHW 格式的 `uint8` 保存。归一化由作业的 `ImageEncoder` 完成，避免重复归一化。
- 描述转为小写，按单词/数字分词，去除标点但保留词内撇号，最多保留 15 个正文词。加上 `<START>`、`<END>` 后长度为 17，不足部分用 `<NULL>` 补齐。
- 只用选中的训练描述建立词表，防止使用验证文本的信息。训练中出现少于 5 次的词，以及验证中的词表外词，映射为 `<UNK>`。当前词表大小为 1,412。
- 保留作业读取器需要的五个字段：`train_images`、`val_images`、`train_captions`、`val_captions`、`vocab`。

这些设置用于构建可复现、规模适中的替代实验数据，不意味着它们与原课程预处理规则完全相同。

具体张量格式、下载来源、校验和及预处理细节见 [COCO_DATA.md](COCO_DATA.md)。本地 `datasets/coco2014_manifest.json` 记录每个配对的图片 ID、标注 ID 和原始描述；`datasets/coco2014_metadata.json` 记录构建参数与数据校验和。

- 普通 RNN 的单步和序列前向、手写反向传播。
- WordEmbedding 和时间序列交叉熵损失。

数值测试通过；三种模型的整体 loss 测试与题目预期一致，差异为 0。真实数据的小批量前向、反向和生成检查也通过。

环境适配包括本地路径定位、跳过非 Colab 环境的 Drive 挂载、CUDA 设备选择，以及 OpenCV 可视化兼容修复。`attention_visualizer` 在绘制文字前，将浮点图片转换成 `uint8`；这只影响显示，不改变模型或损失计算。

## 训练结果与原作业参考目标

本次完整训练配置为 batch size 256、hidden dimension 512、word embedding dimension 256、学习率 0.001、60 epochs，使用 RTX 5070 GPU。

| 模型 | 小样本实验最终 loss | 小样本参考目标 | 完整训练最后一个 batch 的 loss | 完整训练参考目标 |
|---|---:|---:|---:|---:|
| RNN | 0.1808 | < 0.5 | 0.8485 | < 2.0 |
| LSTM | 3.4730 | < 4.0 | 3.8313 | < 1.8 |
| AttentionLSTM | 6.7978 | < 9.0 | 1.0728 | < 0.5 |

三种小样本实验均达到 notebook 的参考目标；完整训练中，LSTM 和 AttentionLSTM 尚未达到原 notebook 的参考值。不能将这种差异直接判定为代码错误，也不能声称已保证满足评分要求：

1. **实验数据不同。** 图片、描述、词表、句子长度及样本分布都可能影响收敛速度和最终 loss，原数据下的参考值不能直接作为替代数据的严格通过线。
2. **当前 loss 仍在下降。** 从保存的逐 batch 记录计算，第 50 轮到第 60 轮的平均 loss：LSTM 为 5.85 → 3.88，AttentionLSTM 为 2.67 → 1.07。说明仍有收敛趋势，但不保证继续训练必然达到参考值。
3. **日志不是全数据评估值。** `train_captioner` 每轮打印的是最后一个训练 batch 的 loss，不是整轮平均值或验证集 loss。上表的完整训练值也采用这一口径。
4. **loss 按句子而非按有效词平均。** 当前实现对所有有效时间步的交叉熵求和，再除以 batch 图片数，忽略 `<NULL>`；这符合题目要求，但句子长度改变会影响数值尺度。不应为使数值更低而更换归一化方式。

另一个需要准确表述的实验条件：当前训练单元格沿用作业的 `torch.randint` 有放回抽样，抽取与训练配对数相同数量的记录；这并非让每个训练配对恰好出现一次。训练助手还沿用固定 batch 顺序，并丢弃不足一个 batch 的尾部数据。本次未修改这些预先提供的训练逻辑。

目前未发现已实现的核心计算存在数学错误，但通过数值测试不等于证明所有边界情况都正确。生成描述在部分验证图片上仍有对象、动作或细节错误；训练 loss 低也不等于泛化表现好。若需要改善结果，应观察验证表现并记录训练条件，而不是只追求更低的训练 loss。

## 为什么会出现 `<UNK>`

`<UNK>` 表示未知词，不是填充符号 `<NULL>`。由于当前词表过滤了低频词，真实描述和生成描述中都可能出现它。

在本次数据中，未知词占正文词数的比例为：训练集 5.23%、验证集 6.42%；含至少一个未知词的描述占比为：训练集 38.3%、验证集 43.0%。这些比例反映了替代词表的限制，不应通过简单删除或屏蔽 `<UNK>` 来掩盖问题。
